GIT COMMANDS USED IN THIS ASSIGNMENT
====================================
Repository: https://github.com/Bhuvanesh66/git-workflow-assignment


STEP 1 - LOCAL REPOSITORY SETUP
-------------------------------
mkdir git-workflow-assignment
    Creates the project folder on the local machine (index.html and about.html were then added to it).

cd git-workflow-assignment
    Moves into the project folder so all following commands run inside it.

git init -b main
    Initializes a new, empty Git repository in the current folder and names the default branch "main".

git status
    Shows the state of the working directory: which files are untracked, modified or staged.


STEP 2 - GIT WORKFLOW EXECUTION
-------------------------------
git add index.html about.html
    Stages the two HTML files so they are included in the next commit.

git commit -m "Initial commit: add index.html and about.html"
    Records the initial state of the project as the first commit, with a descriptive message.

git diff
    Shows line-by-line changes in the working directory that are not yet staged (used after editing index.html).

git add index.html
    Stages the modified index.html file.

git commit -m "Update index.html: add last-updated note"
    Creates the second commit containing the modification to index.html.

git branch feature
    Creates a new branch named "feature" pointing at the current commit.

git branch
    Lists all local branches; the current branch is marked with an asterisk (*).

git checkout feature
    Switches the working directory to the "feature" branch.

git add contact.html about.html
    Stages the new contact page and the updated about page on the feature branch.

git commit -m "Add contact page and link it from about page"
    Commits the feature changes to the "feature" branch only (main is not affected).

git checkout main
    Switches back to the "main" branch.

git merge --no-ff feature -m "Merge branch 'feature' into main"
    Merges the feature branch into main. --no-ff forces a merge commit so the branch activity stays visible in the history.

git log --oneline --graph --decorate --all
    Displays the commit history of all branches as a compact graph, showing where the feature branch split and merged.

git log --stat
    Displays the full commit history (author, date, message) with the files changed in each commit.


STEP 3 - .GITIGNORE IMPLEMENTATION
----------------------------------
cat .gitignore
    Prints the contents of .gitignore, which contains the rules "*.log" (all log files) and "temp/" (the temp folder).

git check-ignore -v debug.log temp/notes.txt
    Verifies that the test files are ignored and shows which .gitignore rule ignores each one.

git add .gitignore
    Stages the .gitignore file so the ignore rules are shared with the repository.

git commit -m "Add .gitignore to ignore .log files and temp/ folder"
    Commits the .gitignore file.


STEP 4 - UNDO OPERATION
-----------------------
git add index.html
git commit -m "Add footer to index.html"
    Makes an additional commit (adds a footer to index.html) that will then be undone.

git log --oneline -3
    Shows the last three commits to confirm the additional commit exists before undoing it.

git revert HEAD --no-edit
    Undoes the last commit by creating a new commit that reverses its changes. Unlike reset, it does not rewrite
    history, so it is safe for shared/pushed branches and the undo stays visible on GitHub.

git show --stat HEAD
    Shows the details of the revert commit and the file it changed.

git diff HEAD~2 HEAD -- index.html
    Compares index.html before the footer commit with the current version; empty output proves the change was fully undone.


STEP 5 - GITHUB INTEGRATION
---------------------------
gh repo create git-workflow-assignment --public
    Creates a new public repository on GitHub using the GitHub CLI (the same can be done from github.com > New repository).

git remote add origin https://github.com/Bhuvanesh66/git-workflow-assignment.git
    Connects the local repository to the GitHub repository under the name "origin".

git remote -v
    Lists the configured remotes and their URLs to confirm the connection.

git push -u origin main
    Uploads the main branch and its full history to GitHub; -u sets origin/main as the upstream for future pushes.

git push origin feature
    Uploads the feature branch to GitHub so the branch activity is visible there as well.


STEP 6 - COMMAND DOCUMENTATION
------------------------------
git add git_commands.txt
    Stages this documentation file.

git commit -m "Add git_commands.txt documenting all Git commands used"
    Commits the documentation file to the repository.
